## 0. Schema canonici

### 0.1 TOOLS.md — Schema per voce (§5.2)

Ogni tool è una voce YAML nel blocco `## Registry` di `TOOLS.md`:

```yaml
- name: tool_name              # snake_case, chiave primaria — deve corrispondere a AllowedCommand.tools_allowed
  display_name: "Display Name" # stringa leggibile
  description: "..."           # cosa fa (1 riga)
  category: sistema|rete|dati|telegram|email|calendario|todo|spesa|social|documenti|visione|audio|skill|utility
  is_dangerous: false          # true → richiede confirmation_gate
  parameters:                  # lista input che il tool accetta
    - name: param_name
      type: string|integer|boolean|array|object
      required: true|false
      description: "..."
  env_required: []             # nomi var env necessarie, lista vuota se nessuna
```

**Regola TOOLS.md:** ogni `name` deve corrispondere a una chiave nel `dispatch()` di `ToolExecutor`. Il file è source-of-truth per l'agente; il DB (`tools` table) è source-of-truth per la UI dashboard.

### 0.2 SKILLS.md — Schema per voce (§5.3)

Ogni skill è una voce YAML nel blocco `## Registry` di `SKILLS.md`:

```yaml
- name: skill_name             # snake_case, deve corrispondere a directory skills/<name>/
  display_name: "Display Name"
  description: "..."
  tools_required:              # ogni elemento DEVE esistere come `name` in TOOLS.md (§G9)
    - tool_name_1
    - tool_name_2
  env_required:                # variabili env, lista vuota se nessuna
    - ENV_VAR
  commands:                    # allowed_commands che puntano a questa skill (via skill_required)
    - command_name
```

**Regola SKILLS.md:** integrità referenziale → nessun `tools_required` può puntare a un tool non presente in TOOLS.md. Verificato da `fd:check-integrity`.

class ConfirmationGate {
