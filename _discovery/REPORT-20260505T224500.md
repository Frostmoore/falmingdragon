## 2. Entry point e flusso di elaborazione

```
Telegram → POST /api/telegram/webhook
  ↓ TelegramAuthMiddleware (valida webhook secret + chat ID allowlist)
  ↓ TelegramWebhookController::handle()
  ↓ TelegramParser (detecta tipo: testo / foto / voce)
  ├─ Foto    → handlePhoto() → Vision skill
  ├─ Voce    → handleVoice() → Whisper diretto → routing NL
  └─ Testo   → CommandRouter::route()
               ↓ confirmation_gate (is_dangerous check)
               ↓ AgentSpawner::spawn()
               ↓ AgentOrchestrator::run() [agentic loop]
               ↓ ToolExecutor::dispatch() [56 tool]
               ↓ TelegramService::sendMessage/sendPhoto/sendVoice()
```

## 9. confirmation_gate (Specifica §5.5)

**Stato:** ✓ **IMPLEMENTATO MA NON ISOLATO**

- Logica presente in `CommandRouter::route()` + `TelegramWebhookController::handleConfirm/handleDeny()`
- Categorie coperte: comandi `is_dangerous=true` nel DB
- **Gap vs specifica:** non è un componente riusabile autonomo con interfaccia dedicata; la logica è embedded nel controller/router. La specifica richiede un componente separato (`confirmation_gate` o equivalente).
- **Gap vs specifica:** le categorie esplicite di §5.5 (sudo, eliminazione file, firewall, DB distruttivo, push git, messaggi a terzi, modifica FLAMINGDRAGON.md) non sono enumerate come enum/costante — sono delegate al flag `is_dangerous` nei seed, senza validazione categoriale.
